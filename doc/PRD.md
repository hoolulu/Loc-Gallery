| 项目 | 说明 |
|------|------|
| 产品名称 | Loc Gallery |
| 版本 | 12.1.0 |
| 文档版本 | 2026-08-08 |

## 1. 产品概述

### 1.1 定位

Loc Gallery 是一款**本地视频画廊 Web 应用**：在浏览器中浏览、搜索、播放本机视频库，支持收藏、播放历史、专辑整理与缩略图管理。所有数据与媒体文件均保存在用户本机，无需账号与云端。

### 1.2 目标用户

- 在本地硬盘管理大量视频资源的个人用户
- 需要按分类/文件夹浏览、快速预览与续播的场景
- 希望用浏览器统一访问多目录「视频库」的用户

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| 本地优先 | 视频不离开本机；服务仅监听 localhost |
| 开箱即用 | 配置视频库路径后即可扫描、浏览、播放 |
| 智能播放 | 自动识别容器/编码；movi-player WASM demux 直连，异常结构自动重封装，硬解不支持时外部播放器兜底 |
| 高效浏览 | 虚拟滚动网格、缩略图后台生成、SSE 进度推送 |
| 可整理 | 收藏、历史、专辑、批量操作、文件夹管理 |

## 2. 技术架构

### 2.1 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | Vue 3、TypeScript、Vite、Pinia、Vue Router、Tailwind CSS 4 |
| 播放 | movi-player web 组件（WASM demux + WebCodecs 硬解直连） |
| 后端 | Python 3、FastAPI、uvicorn |
| 媒体处理 | ffmpeg、ffprobe |
| 实时推送 | Server-Sent Events（SSE） |
| 数据存储 | JSON 文件 + 本地缓存目录（`data/`） |

### 2.2 部署形态

- **开发模式**：`python restart.py` — 单端口 `3460`，Vite 热更新 + API 代理
- **生产模式**：`python restart.py --build` — 构建前端静态资源后由后端统一托管
- 默认访问：`http://127.0.0.1:3460`

### 2.3 系统结构

```
浏览器 (Vue SPA)
    │ HTTP / SSE
    ▼
FastAPI 服务 (loc_gallery)
    ├── 视频索引与扫描 (scanner)
    ├── 缩略图任务 (thumb_manager)
    ├── 重封装修复 (remux_manager，含后台批量预修复)
    ├── 格式探测与播放策略 (media_probe)
    ├── 外部播放器兜底 (server 内 _launch_external_player)
    └── 设置 / 多库 / 收藏 / 历史 / 专辑 (settings_store, stores)
    │
    ├── 用户视频目录（libraries 配置）
    └── data/（索引、缩略图、缓存、设置）
```

### 2.4 前端模块

| 模块 | 职责 |
|------|------|
| `pages/` | 首页浏览、收藏、历史、专辑列表与详情 |
| `components/layout/` | 顶栏、分类侧栏、批量操作栏、进度条 |
| `components/gallery/` | 视频卡片、虚拟网格、分页 |
| `components/player/` | 全屏播放器与播放列表 |
| `components/dialogs/` | 设置、专辑选择、缩略图选择、非标准格式提示等 |
| `stores/` | gallery、library、player、settings、album、ui |
| `composables/` | 播放、浏览导航、右键菜单、SSE、缩略图进度等 |

## 3. 功能需求

### 3.1 视频库管理

- 支持多个视频库，每个库包含：**别名** + **本地文件夹路径**
- 切换当前活动库后，分类、视频列表、收藏/历史/专辑均按库隔离
- 通过设置或 API 新增、编辑、删除库；支持系统文件夹选择器选取路径
- **刷新（重新扫描）**：更新索引、 reconcile 缩略图、重建格式索引、补全时长等

### 3.2 画廊浏览（首页）

**经典布局**（侧栏 + 网格）与 **影院布局**（全宽网格）两种预设，见 §4。

- 按**分类**浏览；分类支持星标、排序模式、拖拽顺序
- 分类下支持**子文件夹**树形导航与面包屑
- **搜索**：标题/文件名模糊匹配，防抖请求
- **排序**：默认顺序、随机、文件名、标题、修改时间、大小等
- **格式筛选**：全部格式 / 无法播放（浏览器硬解不支持的编码）
- **分页**：每页条数可配置（经典默认 45，影院默认 50，支持自定义）
- **随机播放**：在当前列表上下文内随机起播
- **虚拟滚动**：大列表下保持滚动性能

### 3.3 视频卡片

每张卡片展示：

- 16:9 缩略图（生成中/失败占位）
- 标题、时长角标
- 可选：播放进度条、播放次数
- **格式角标**（仅在有需要用户关注时显示，见 §3.10）
- 收藏按钮、加入专辑按钮
- 悬停路径提示（PathTip）：目录、文件名、编码、大小、收藏/播放信息

支持**批量模式**：多选后批量收藏、删除、移动分类、加入专辑、重命名等。

### 3.4 收藏与历史

| 视图 | 功能 |
|------|------|
| 我的收藏 | 仅展示已收藏视频，支持分页与播放 |
| 最近播放 | 按播放时间排序，展示进度与播放次数 |

播放位置与历史记录在播放过程中自动保存；可在设置中配置历史保留天数并一键清空。

### 3.5 专辑

- 创建/编辑/删除专辑（名称、描述）
- 专辑封面：指定库内某一视频的缩略图
- 专辑详情：视频列表、播放全部、从专辑移除
- 右键菜单：打开、编辑、播放全部、删除
- 单视频或多视频**加入专辑**（勾选已有专辑）

### 3.6 播放器

#### 3.6.1 播放模式

| 模式 | 说明 |
|------|------|
| movi-player 内置 | 默认；全屏覆盖层，不离开浏览页；WASM demux + Range 直连 |
| 外部播放器 | 无法硬解时弹窗调用（VLC/MPC-HC/PotPlayer 等，路径可配置或自动探测） |

#### 3.6.2 播放策略（自动）

后端 `media_probe` 对每个文件生成**播放计划**，前端按 `mode` 执行：

| mode | 行为 |
|------|------|
| `direct` | movi-player 直连 `/api/stream/{id}`（WASM demux） |
| `remux` | 碎片化/多段 mdat：标记为可重封装，前端自动修复后直连 |
| `unsupported` | 硬解不支持（mpeg2/VC-1/WMV 等）→ 提示用外部播放器打开 |

策略考虑因素：容器（MP4/WebM/MKV/TS…）、视频编码（H.264/HEVC/AV1/VP9…）、MP4 结构（碎片化、多段 mdat）；文件大小不再影响策略（统一直连）。

**现代编码直连**：AV1/HEVC/VP9 一律尝试浏览器直连（movi-player），失败由前端 watchdog 兜底重封装或提示外部播放器。

#### 3.6.3 播放器功能

- 续播（记忆进度）、连播（列表播完自动下一集）
- 右侧播放列表：排序、无限滚动加载、当前项高亮
- 收藏、加入专辑
- **播放页快捷键**（页面级，替代油猴脚本；movi 内置快捷键无条件关闭）：
  - C / X / Z：加速 / 正常速度 / 减速（0.1 步进，0.25x~2x，OSD 显示倍速）
  - 空格：播放 / 暂停；← / →：快退 / 快进 5 秒；Ctrl + ← / →：快退 / 快进 30 秒
  - Enter：全屏切换；Esc：关闭播放器；上一集/下一集（可配置键）
- 滚轮快进/快退（可配置秒数）
- 播放列表与 Media Session 集成（系统媒体键）
- **多音轨 / 多字幕选择**：MKV 等多轨容器通过控制栏音轨/字幕按钮（或右键菜单）切换；默认自动选中文字幕（无中文则选第一条字幕轨）
- 播放失败弹窗：用外部播放器打开 / 取消（自动修复已先行，不再手动修）

### 3.7 缩略图

- 后台队列生成，多 worker 并发；空闲时可扫描缺失缩略图
- 顶栏显示生成/队列状态芯片与总进度条（可配置显示策略）
- 单视频：重新生成、从多个候选帧中挑选、换一批候选
- 批量重新生成；失败列表查看与全部重试
- 可配置：截图位置、候选数量、自动择优、抖动范围、并发数等

### 3.8 文件与文件夹操作

- 重命名视频文件（同步更新索引 ID）
- 删除视频（移入系统回收站）
- 批量移动到其他分类
- 文件夹：重命名、删除（含子目录视频）、移动到另一分类
- 打开视频所在文件夹（资源管理器）
- 流复制修复（remux）：将部分碎片化 MP4 修复为标准 MP4 后播放

### 3.9 设置

全屏弹窗，左侧分类导航：

| 分类 | 内容 |
|------|------|
| 视频库 | 库管理、外观（暗色/亮色、经典/影院布局） |
| 播放 | 外部播放器路径、后台自动修复、续播/连播、悬停预览（段数/时长、浮层钉住）、滚轮快进、上/下一集键 |
| 缩略图 | 生成参数与进度条显示 |
| 其他 | 默认每页条数、历史保留、清空历史、重启服务 |

支持**全局设置**与**当前库设置**分 scope 保存。

### 3.10 格式角标与筛选

角标用于提示**需要用户留意**的格式，而非标记所有非 H.264 文件。

**显示角标**（示例）：

| 角标 | 含义 |
|------|------|
| 特殊 | 播放时可能需要转码（如部分非 MP4 容器） |
| 可修复 | 多段交错 MP4，可流复制修复 |
| 交错 | 多段 mdat 交错结构 |
| 伪装 | 伪装为其他扩展名的 MPEG-TS 等 |
| 碎片化 | 碎片化 MP4，建议 PotPlayer 或修复 |
| 无法播放 | 浏览器不支持的编码 |

**不显示角标**：标准 H.264 与 HEVC/AV1/VP9 现代编码直连、可自动修复的碎片化 MP4 等情况。

格式筛选与角标分类共用后端 `format_index`；列表展示时优先按最新播放计划重新分类，避免索引过期。

## 5. 数据模型（概要）

数据目录默认：`项目根目录/data/`

| 路径 | 内容 |
|------|------|
| `libraries.json` | 视频库注册表 |
| `libraries/{id}/` | 单库数据：索引、收藏、历史、专辑、缩略图、缓存 |
| `settings.json` | 全局设置 |
| `libraries/{id}/settings.json` | 库级设置覆盖 |

**建议保留（用户数据）**：`.thumbs/`、`favorites.json`、`play_history.json`、`albums.json`、`category_meta.json`、库级 `settings.json`。

**可安全清理（可再生缓存）**：`cache/playback_plans.json`、`cache/format_index.json`（会重新探测）、`data/logs/`；旧版遗留的 `cache/hls/`（HLS 切片，已废弃）如有也可清理。

清理命令：`python scripts/clean_cache.py`

视频条目主要字段：id、title、filename、path、category、subfolder、size、mtime、duration、缩略图状态、收藏与播放元数据、专辑关联、格式分类等。

## 6. API 概要

REST 基础路径：`/api`  
健康检查：`GET /api/health`  
实时事件：`GET /api/events`（SSE）

主要端点分组：

| 分组 | 示例 |
|------|------|
| 库 | `GET/POST /api/libraries`，`POST .../activate` |
| 分类/文件夹 | `GET /api/categories`，`GET /api/folders`，文件夹增删改移 |
| 视频 | `GET /api/videos`，`GET /api/videos/{id}`，删除/重命名/移动 |
| 收藏/历史 | toggle、summary、record、position、clear |
| 专辑 | CRUD、视频增删排序、封面 |
| 播放 | `GET /api/play/info/{id}`，`GET /api/stream/{id}`（Range 直连），`POST /api/play-external/{id}`（外部播放器），`GET /api/play/badges` |
| 缩略图 | status、regenerate、candidates、pick、failed |
| 设置 | `GET/POST /api/settings`，`POST /api/service/restart` |
| 维护 | `POST /api/rescan` |

前端开发时由 Vite 将 `/api` 代理至后端。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 安全 | 仅绑定 127.0.0.1；不对外暴露 |
| 性能 | 列表 API 批量读取索引；虚拟滚动；缩略图懒加载 |
| 可靠性 | 播放会话 generation 防止竞态 |
| 可维护性 | 前后端分离；Pinia 状态集中；播放/探测逻辑在后端单点决策 |
| 兼容性 | 以 Chromium 内核浏览器为主；movi-player 经 WASM demux + WebCodecs 直连 H.264/HEVC/AV1/VP9，解码依赖系统/GPU 能力，缺失时外部播放器兜底 |
